- Blocker: The complete drag lifecycle is not generation-bound, so a prior drag can release a newer accepted gesture. `WindowDragController.finish` clears its active drag immediately and returns a deferred completion ([windows/src/window-drag.ts](C:/sudy/github/DesktopPet/windows/src/window-drag.ts:75)); a new pointerdown may therefore begin a new lease before the old completion runs. When the old completion eventually calls `finishDrag` ([windows/src/window-drag.ts](C:/sudy/github/DesktopPet/windows/src/window-drag.ts:147)), [windows/src/pet-window.ts](C:/sudy/github/DesktopPet/windows/src/pet-window.ts:367) calls `finishPetInteractionLease()` without the original lease token. `PetInteractionLease.finish()` then captures whatever lease is currently active ([windows/src/pet-interaction-lease.ts](C:/sudy/github/DesktopPet/windows/src/pet-interaction-lease.ts:35)), which is the newer gesture, and deactivates it. This violates the required overlapping-lifecycle guarantee and can make the new drag click-through before its pointer capture ends. Existing coverage only tests a direct `finish()` before a later `begin()`, not a delayed `WindowDragController` completion followed by a newer `pointerdown` ([windows/src/pet-interaction-lease.test.ts](C:/sudy/github/DesktopPet/windows/src/pet-interaction-lease.test.ts:32), [windows/src/pet-window-drag.test.ts](C:/sudy/github/DesktopPet/windows/src/pet-window-drag.test.ts:9)).
