# Windows configuration and idle-performance review

Scope: read-only review of the requested Windows renderer, settings, instance-store, roam, sprite, i18n, and performance-contract files. No repository source file was edited.

## Review

- Blocker (high): Quick bubbles can remain visible indefinitely after their nominal expiry. In `windows/src/pet-window.ts:190-199`, the quick-bubble branch returns before deriving or updating `renderSig`. The prior normal-state signature therefore remains cached. Once `quickBubbleUntil` passes, `windows/src/pet-window.ts:211-225` recomputes that same signature and skips `bubble.renderLine()`/`bubble.hide()`, leaving the quick text rendered. This is directly reproducible from `showQuickBubble()` at `windows/src/pet-window.ts:149-152`, which sets only the text and deadline.

- Note (high performance regression): Temporary diagnostics in `windows/src/roam/engine.ts:9-17,130-137` and `windows/src/roam/modes.ts:29-36,143-155,172` are not idle-safe. The throttles still issue `log_debug` IPC at most once every 300ms per module, including while an idle/resting roam loop checks at 200ms (`engine.ts:39-45,196-200`). Their formatted strings are also constructed every mode tick before throttling. This conflicts with the stated purpose of `IDLE_TICK_MS`. Remove these diagnostics before shipping, or place them behind an explicitly disabled diagnostic flag. Do not retain them as a performance improvement.

- Correct: The roam engine already makes defensible idle reductions: stationary states use a 200ms rather than 30ms loop (`windows/src/roam/engine.ts:39-45,196-200`), monitor data is cached for 500ms (`windows/src/roam/environment.ts:31-49`), and expensive system-window enumeration is requested only for climb mode (`environment.ts:81-96`, `engine.ts:127-130`). `windows/src/performance-contract.test.ts:36-40` asserts the latter.

- Correct: Per-instance roam configuration has a suitable persistence and live-update path. `PetInstance` is normalized and stored in `windows/src/pets.ts:3-13,39-54,74-84`; Settings saves selected-instance changes without native-window reconciliation and emits only to its owner (`windows/src/settings.ts:828-856`, especially 831-834); the owning renderer refreshes its cache on that event (`windows/src/pet-window.ts:264-274`). The current contract test protects this routing and no-reconcile behavior (`windows/src/performance-contract.test.ts:13-24,61-68`).

- Correct: Existing pause semantics are not a single duration. Wander picks a random pause in `[1200, 3500)` ms at `windows/src/roam/modes.ts:123-133`, using `IDLE_MS_MIN` and `IDLE_MS_MAX` from `windows/src/roam/types.ts:45-46`. Climb independently uses the same range at `modes.ts:174-181`.

- Correct: The current quick-bubble duration is an explicit 4,000ms default (`windows/src/pet-window.ts:130-152`). Quick content, appearance, and preset settings are global settings, not instance properties (`windows/src/settings.ts:768-819,1429-1466`), and the emitted event intentionally reaches all desktop pets (`pet-window.ts:283-287`). This supports a global quick-bubble-duration setting.

## Minimal implementation path

### 1. Fix quick-bubble expiry

1. In `windows/src/pet-window.ts:149-152`, invalidate the normal render cache before calling `render()`, for example assign `renderSig = ""` in `showQuickBubble()`. On the first normal render after the deadline, the derived signature at line 211 will then differ and restore the mood bubble or hide it. This is the minimal correction; it changes no event routing or timer ownership.
2. Keep the existing 500ms render interval (`pet-window.ts:231`). The restored normal display will occur in the interval `[configured duration, configured duration + 500ms)`. Add a one-shot timeout only if product requires an exact wall-clock dismissal; that adds cancellation/token lifecycle complexity and is not necessary to fix the stale rendering defect.
3. Replace `QUICK_BUBBLE_MS` with `DEFAULT_QUICK_BUBBLE_DURATION_MS = 4000` plus a small local reader in this file. The reader should parse one global localStorage key, accept only finite values at or above the approved lower bound, and otherwise return 4000. Read it when `showQuickBubble()` starts, so a message has a stable duration even if Settings changes while it is already visible.

### 2. Persist and expose wander pause

Recommended scope: per desktop instance, because roam mode and speed already have that scope in `PetInstance` (`windows/src/pets.ts:9-11`) and are edited in the selected-instance Roam panel (`windows/settings.html:152-165`, `windows/src/settings.ts:821-863`). Quick-bubble duration should remain global because it is in the Bubble panel and broadcasts to every pet.

1. Add one explicitly named pause field to `PetInstance` in `windows/src/pets.ts:3-13`, and normalize missing/invalid values in `normalizeInstance()` at lines 39-54. Keep store version 1: its normalizer already provides backward-compatible defaults for absent fields. Add the default to both constructors: migration at lines 90-105 and Settings' `instanceFromLibrary()` at `windows/src/settings.ts:65-75`.
2. Extend `Config` and `normalizeConfig()` in `windows/src/roam/types.ts:29-35,110-116` with the same field. Add the legacy global fallback in `loadConfig()` at lines 118-132 only for non-instance callers. Extend the injected per-instance source at `windows/src/pet-window.ts:40-45` to return the stored field, so it remains in the current owner-only update path.
3. At `windows/src/roam/modes.ts:127-130`, replace the hard-coded random wander deadline with the configured wander value. Do not modify the climb edge pause at lines 174-176: the requested setting is wander-specific, and changing climb is an unrelated behavior change.
4. Add one numeric control in the existing Roam `gcard` in `windows/settings.html:153-164`, after speed. Bind it in `initPetControls()` (`windows/src/settings.ts:821-863`) through the existing `updateSelected()` path. Disable/sync it alongside size, mode, and speed. This preserves no-native-reconcile slider behavior.
5. Add English source strings through `applyStatic()` in `windows/src/settings.ts:1315-1321` and translated entries in each `DICT` block in `windows/src/i18n.ts`: Vietnamese near lines 47-53 and 239-246, Simplified Chinese near lines 351-357 and 543-550, Traditional Chinese near lines 655-661 and 845-852. Existing translated `seconds` can be reused; add distinct keys for the wander and quick-duration labels.

### 3. Persist and expose quick-bubble duration

1. Add the control to the existing Quick bubbles group in `windows/settings.html:244-251`, not the per-instance Roam group. Bind it in `initQuickBubbles()` (`windows/src/settings.ts:1451-1466`) with a dedicated global key and the same parse/default policy used by the renderer.
2. The field does not need `bubble-changed` for future messages because each renderer reads the shared value when it receives a quick-bubble event. Avoid broadcasting solely for this setting: a global wake-up would be unnecessary idle work. If product chooses to resize an already visible quick bubble's remaining lifetime, that is a separate, explicit behavior and does require a broadcast plus timer/re-render semantics.

## Defaults and bounds

- Quick-bubble duration default: **4 seconds**, exactly justified by `QUICK_BUBBLE_MS = 4000` at `windows/src/pet-window.ts:133`.
- Minimum for user-entered duration: **1 second**, justified by the existing persisted idle-animation interval reader (`windows/src/pet.ts:56-62`) and settings numeric control (`windows/src/settings.ts:1036-1045`). Reuse `type="number"`, `min="1"`, and `step="1"` rather than inventing a slider range.
- Maximum: **no existing pattern justifies a new maximum**. The existing interval control has no `max` and accepts every finite value `>= 1`. Do not introduce an arbitrary cap without product approval.
- Wander pause current behavior: a random **1.2 to under 3.5 seconds**, not a scalar. A fixed default cannot exactly preserve it. A scalar fixed value of 2 seconds or 2.35 seconds changes the distribution; neither is established by current code.

## Required product decision

Before implementation, approve one definition for **Wander pause**:

1. Fixed duration per instance: choose its default and whether fractional seconds are permitted. The existing UI convention supports whole seconds with a minimum of 1, but does not identify a fixed default.
2. Random range per instance: store/edit a minimum and maximum (or a selectable range) and default to the existing 1.2-3.5 seconds. This is the only option that preserves present behavior exactly, but adds a second persisted field and control.

Also confirm whether a duration change affects only subsequently shown quick bubbles (recommended, minimal) or an already visible bubble. The current behavior has no live-duration precedent.

- Extend `windows/src/performance-contract.test.ts` to ensure the new selected-instance control remains inside `updateSelected()` with `syncWindows: false`, and to prohibit production `roam-diag`/`roam-mode` periodic logging unless diagnostics are explicitly gated.

## Residual risks

- Current targeted tests do not exercise `pet-window.ts`'s quick-bubble expiry path; the permanent-bubble defect therefore passes the current suite.
- The requested scalar wander setting changes current randomized behavior unless product selects a range design.
- A strict maximum duration, per-instance quick duration, and live modification of an already visible bubble are product decisions not evidenced by the current implementation.
- The worktree has extensive unrelated modified and untracked files. This review did not revert, stage, or edit them.
