# Code Context

## 状态

结论：旧 Tauri 动画选择器并非 macOS 当前实现的逐字段移植，而是建立在共同的“状态 → spritesheet clip/行”契约之上，额外加入了 **全局 idle 播放列表、多选、随机/顺序模式和切换间隔**。

关键差异：

- **共同契约**
  - spritesheet 按透明沟槽切成二维 `clips`，每一行是一个动画 clip，每个 clip 包含多帧。
  - 用户按宠物状态选择 clip。
  - 默认打开 `working`。
  - 非 idle 状态单选。
  - hover 时播放该 clip，离开后回到首帧。
  - clip 索引读取和实际渲染均对 clip 数量做一定程度的下标钳制。
- **旧 Tauri 特有**
  - idle 是不可清空的多选播放列表。
  - idle 支持 `random` / `sequential`。
  - idle clip 切换间隔默认 5 秒、最小 1 秒。
  - 数据保存在全局 `localStorage`，没有按 pet/pack 隔离。
- **当前 macOS 特有**
  - 所有状态（包括 idle）均为单选。
  - 支持额外状态 `sleepy`、`levelup`。
  - binding 按 `pack.id` 隔离，保存为 `UserDefaults` 中的 JSON `[String: Int]`。
  - 没有 idle playlist、mode 或 interval 数据结构。
  - 当前默认映射是按状态顺序 `0...6` 分配，而不是旧 Tauri 的语义行号 `0/7/6/3/4`。

## Architecture

```text
旧 Tauri
settings.html
  └─ #anim-mood / #anim-grid
       └─ settings.ts:initAnimations()
            ├─ slice(image) → Rect[][]
            ├─ ap_bind_<mood>
            ├─ ap_idle_clips
            ├─ ap_idle_mode
            └─ ap_idle_interval
                    ↓
              pet.ts:Pet.setState()
                    ├─ 普通 mood → 单个 row
                    └─ idle → timer 周期切换 idleRow
```

```text
当前 macOS
SpriteSlicer.loadPack()
  └─ ImagePetPack.clips: [[NSImage]]
       ↓
SetupView.AnimationPicker
  └─ PetBindingsStore.setClip()
       └─ UserDefaults["desktoppet.bindings.<packId>"]
            ↓
PetView
  └─ PetBindingsStore.clipIndex(...)
       └─ ImageSpriteView(pack.clip(index))
```

共同不变量是：

> spritesheet 的一条切片行是一个可绑定动画 clip；宠物 mood 在运行时解析成 clip 索引。

idle playlist 并不属于当前 macOS 的共同数据模型；它是旧 Tauri 在该不变量之上添加的播放策略。

## Review Findings

1. **high：默认映射存在跨平台语义冲突**  
   `2c9b701~1:windows/src/settings.ts:897-920` 使用 `working=7 / waiting=6`，而 `Sources/App/PetBindings.swift:12-19` 使用 `working=1 / waiting=2`。若直接照旧 UI 恢复但继续使用当前 macOS defaults，新用户看到的默认动画会不同。

2. **high：旧 Tauri idle 设置是全局的，不是 per-pet**  
   `ap_idle_clips`、`ap_idle_mode`、`ap_idle_interval` 和 `ap_bind_<mood>` 均不含 pet ID。切换宠物后，同一组 clip 索引会应用到不同 spritesheet。当前 macOS 的 binding 则按 `packId` 隔离。若把旧 key 当作共同契约，会破坏当前 per-pack 语义。

3. **medium：旧 Tauri idle playlist 的越界清洗不完整**  
   `windows/src/settings.ts:922-931` 只过滤负数和非数值，不过滤 `>= clips.length`。运行时最终在 `windows/src/pet.ts:269-275` 上钳制，因此多个无效索引可能实际指向同一个最后 clip，但设置 grid 不会显示这些索引为已选。

4. **medium：旧模式值没有严格归一化**  
   设置页 `readIdleMode()` 对任意已保存字符串原样返回；运行时只有精确 `"random"` 才随机，其他所有值都按 sequential。证据：`windows/src/settings.ts:934,1043-1049`、`windows/src/pet.ts:239-246`。

5. **low：Clear 的产品文案与行为不完全一致**  
   “Clear” 不会清空 playlist，而是重置为 `[boundClip("idle")]`，以维护“至少一个 idle clip”的不变量。证据：`windows/src/settings.ts:974-978,1025-1028`。

6. **low：hover 预览速度不是当前 mood 的实际速度**  
   旧 Tauri 固定 125ms/帧；当前 macOS 固定以 `.working` 的 FPS 预览，即使用户正在编辑 idle/waiting。它们都表达“hover 动态预览”，但不是运行时精确预演。证据：`windows/src/settings.ts:985-995`、`Sources/App/SetupView.swift:919-924`。

## Residual Risks

- 本次按要求重点检查了旧 `settings.ts`、`settings.html` 和必要的 `pet.ts` 消费端；没有审计旧 Tauri 所有迁移/清理逻辑，因此不能证明这些 localStorage key 在更早版本中从未存在其他格式。
- 当前工作树已有大量与本任务无关的修改和未跟踪文件；本次没有修改、暂存或清理它们。
- “共同契约”是根据两端数据流和源码注释还原；没有产品规格文档证明 idle playlist 曾计划成为 macOS 跨平台契约。
- 未运行应用级手工 UI，因为任务限定只读源码还原；hover 和 timer 行为由代码路径静态核验。
