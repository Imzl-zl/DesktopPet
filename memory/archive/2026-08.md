## [2026-08-07 | 启动必现"目标凭据已存在且内容不同"误报：P/Invoke CharSet 根因]
- **Events**：用户报每次启动弹"模型连接的目标凭据已存在且内容不同，未修改配置"。静态排查矛盾：providers.json 引用 `myovo-key`（存在），但目标凭据 `provider/model/myovo/api-key` 用独立 CredRead 探测为 NOT_FOUND——不可能触发 target-conflict。用引用真实 FileJsonStore+WindowsCredentialStore 的临时控制台复现：**迁移器确实抛 target-conflict**；全量枚举凭据发现两条乱码名凭据（`敄歳潴偰瑥...`），其 target 名 UTF-16LE hex 正是 `DesktopPet/provider/model/myovo` 的**紧凑 ASCII**，写入时间恰为每次启动时刻。
- **Changes**：根因 = `CredNative.Credential` 结构体 `[StructLayout(Sequential)]` 缺 `CharSet.Unicode`，string 字段按 ANSI 编组：`CredWrite` 把 target 名以 ANSI 字节交给系统，系统按 CREDENTIALW(UTF-16) 解释成乱码；随后 `CredRead(好名字)` 永远 NOT_FOUND → 迁移器 `Set` 后读回 null ≠ 源 → 误判 target-conflict，**每次启动报错并累积一条垃圾凭据**。修复：加 `CharSet = CharSet.Unicode`；清理 2 条垃圾凭据；迁移器重新执行成功（providers.json 已指向新引用、旧 `myovo-key` 自动删除、凭据内容无损验证）；新增 `WindowsCredentialStoreTests.SetGetDelete_RoundTrip_PreservesTargetNameExactly` 真实凭据 round-trip 回归测试（Infra.Tests 104 全过）。
- **Insights**：① P/Invoke 结构体含 string 字段必须显式 CharSet.Unicode，缺省按 ANSI 编组是静默损坏——单测（InMemory 假凭据）覆盖不到，必须真实 Credential Manager round-trip；② 迁移器把"Set 后读回不一致"统一映射为 target-conflict 会掩盖写入损坏类故障，故障分类应区分"目标已存在且不同"与"写入后读回异常"；③ 垃圾凭据名不匹配 `DesktopPet/*` 过滤器（系统视角名字已是乱码），`DeleteAll` 清理不到，只能全量枚举按 UTF-16 hex 特征识别；④ 诊断优先用真实代码路径复现（临时 console 引用 Infra），不要停留在静态推演。
